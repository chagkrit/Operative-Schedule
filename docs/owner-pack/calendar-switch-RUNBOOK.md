# คู่มือเจ้าของ: สลับปฏิทินหลัก (Google Calendar)

คู่มือนี้สำหรับผู้ดูแลระบบ ใช้เมื่อต้องการย้ายข้อมูลคิวไปอยู่ในปฏิทินของบัญชี Google อื่น (เช่น ปฏิทิน "OR Queue" ของบัญชีใหม่) หรือต่ออายุ token หลังสลับแล้ว ไม่มี token, รหัสปฏิทิน หรือคีย์จริงในไฟล์นี้ ใช้ค่าตัวอย่างในวงเล็บ `<...>` แทน

## ภาพรวมที่ต้องรู้ก่อน

- **จนกว่าจะสลับครั้งแรก ระบบไม่เปลี่ยนอะไร** การเชื่อมปฏิทินใหม่ใน `/admin` เก็บไว้เป็น "ปฏิทินใหม่ที่เชื่อมไว้" เท่านั้น แอปยังใช้ `GOOGLE_CALENDAR_ID` และ `GOOGLE_REFRESH_TOKEN` จาก Vercel เหมือนเดิม และวิธีต่ออายุแบบเดิม (ใส่ refresh token ใหม่ใน Vercel แล้ว Redeploy) ยังใช้ได้
- **หลังสลับครั้งแรก** ปฏิทินหลักจะถูกบันทึกในไฟล์ตั้งค่าที่เข้ารหัสด้วย `CALENDAR_SETTINGS_KEY` ค่า `GOOGLE_REFRESH_TOKEN` ใน Vercel จะไม่ควบคุมปฏิทินอีกต่อไป (ดูหัวข้อ "ต่ออายุ token หลังสลับแล้ว")
- ขณะสลับ ระบบ **หยุดการบันทึก (ลงคิว สลับวัน แก้ ยกเลิก) ประมาณ 10–15 นาที** (หน้าจอแจ้งไว้แล้ว) การดูตารางและค้นหายังใช้ได้ตามปกติ
- ปฏิทินที่ใช้อยู่เดิม **ไม่ถูกแก้ไขหรือลบ** และจะถูกบันทึกเป็น "ปฏิทินก่อนหน้า"
- สิทธิ์ Calendar ที่ใช้มีตัวเดียวคือ `calendar.events` (ตัวเดียวกับที่สคริปต์ token ขอ) การตรวจตอนเชื่อมอ่านรายการ event ของปฏิทินด้วยสิทธิ์นี้
- เหตุการณ์ที่คัดลอกยังคงรหัสเดิม และรายงานเวลารอยังใช้วันที่สร้าง/แก้ไขเดิมจาก `orig_created` / `orig_updated`

## ขั้นตอนสลับ (ตามลำดับ)

1. **สร้างคีย์ตั้งค่า** รัน `openssl rand -base64 32` ที่เทอร์มินัล
2. **ใส่ใน Vercel** เพิ่ม Environment Variable ชื่อ `CALENDAR_SETTINGS_KEY` ค่า = ผลจากข้อ 1 เลือก Environment = Production และติ๊ก **Sensitive** แล้ว **Redeploy** เก็บสำเนาคีย์ไว้ในโปรแกรมจัดการรหัสผ่านของเจ้าของ ห้ามใส่ในโค้ดหรือ commit
   - ถ้าคีย์หายหรือถูกเปลี่ยน token ที่เก็บไว้จะถอดรหัสไม่ได้ ระบบจะอ่านการตั้งค่าไม่ได้และปิดการเรียก Calendar ทั้งหมดด้วย HTTP 503 ข้อความ `อ่านการตั้งค่าปฏิทินไม่สำเร็จ` ต้องใส่คีย์เดิมกลับ หรือเชื่อมปฏิทินใหม่อีกครั้ง
3. **ขอ refresh token ของบัญชีใหม่** หยุด `npm run dev` แล้วรัน
   `node --env-file=.env.local scripts/get-calendar-refresh-token.mjs --email <new-account@example.com>`
   เปิดลิงก์ที่แสดงและเข้าสู่ระบบด้วยบัญชีนั้น (สคริปต์ใช้ได้กับทุกบัญชี) บัญชีต้องเป็นเจ้าของปฏิทินปลายทาง (ปฏิทิน "OR Queue" ที่เจ้าของสร้างไว้แล้ว) สคริปต์พิมพ์ token ที่เทอร์มินัลเท่านั้น ไม่เขียนลงไฟล์
4. **เชื่อมที่ `/admin`** ในส่วน "ปฏิทินหลัก (Google Calendar)" กรอกอีเมล Google ของปฏิทินใหม่, รหัสปฏิทิน (calendar id) และ refresh token แล้วกด "เชื่อมต่อปฏิทินใหม่" ระบบตรวจว่าเข้าถึงปฏิทินนั้นได้ (ขั้นนี้ยังไม่เปลี่ยนปฏิทินหลัก)
5. **ตรวจตัวอย่าง** กด "ตรวจตัวอย่างก่อนสลับ" แล้วดูตัวเลขให้ครบ: จำนวนข้อมูลที่จะคัดลอกแต่ละประเภท, "ข้ามไป", "รายการซ้ำ (recurring)" และคำเตือนว่าปฏิทินปลายทางไม่ว่าง (ปลายทางควรว่าง) ถ้าตัวเลขไม่ตรงกับที่คาดหรือปลายทางไม่ใช่ปฏิทินที่ถูกต้อง อย่าสลับ
6. **ประกาศช่วงหยุดบันทึก** แจ้งผู้ใช้ทุกคนว่าจะลงคิวไม่ได้ประมาณ 10–15 นาที และห้ามปิดหน้า `/admin` ระหว่างสลับ
7. **กดสลับ** แล้วกด "ยืนยันสลับปฏิทิน" รอจนหน้าจอแจ้งผล
   - ปฏิทินใหญ่อาจต้องกดสลับหลายรอบ แต่ละรอบทำงานสูงสุดราว 2.5–3 นาที (ช่วงคัดลอก 150 วินาที เพดานรวม 170 วินาที) และรอบถัดไปทำต่อได้ถูก event ที่คัดลอกแล้วจะถูกข้าม ถ้าหน้าจอบอกให้กดสลับอีกครั้ง ให้กดต่อ
8. **ตรวจว่าตารางเหมือนเดิม** เปิดหน้าตาราง ดูหลายเดือน เทียบจำนวนเคส วันปิดรับคิว และวันที่ staff ไม่ว่าง
9. **แจ้งทุกคน: ห้ามแก้ในปฏิทินโดยตรง** ให้ลงคิว แก้ ยกเลิก และจัดการวันต่าง ๆ ผ่านแอปเท่านั้น (ห้ามแก้ใน Google Calendar โดยตรง)

## ปลดล็อก

ระหว่างสลับระบบล็อกการสลับไว้ ล็อกหมดอายุเองใน 20 นาที ถ้าหน้า `/admin` แสดงว่าล็อกค้างและแน่ใจว่าไม่มีการสลับกำลังทำงานอยู่ จึงกด "ปลดล็อก" **ห้ามกดปลดล็อกขณะที่การสลับยังทำงานอยู่** เพราะอาจตัดการสลับให้ขาดกลางคัน (ถ้าล็อกเพิ่งเกิดไม่ถึง 1 นาที ระบบให้ติ๊กยืนยันก่อน) หลังสลับเสร็จระบบยังคงล็อกต่ออีกประมาณ 35 วินาที เป็นเรื่องปกติ

## ต่ออายุ token หลังสลับแล้ว

หลังสลับครั้งแรก การแก้ `GOOGLE_REFRESH_TOKEN` ใน Vercel **ไม่มีผลต่อปฏิทิน** ถ้า token ของปฏิทินหลักหมดอายุหรือถูกเพิกถอน (หน้าแอปแจ้ง 503 ว่าการเชื่อมหมดอายุ):

1. รันสคริปต์ในข้อ 3 อีกครั้งด้วย `--email` ของบัญชีเดิม
2. ที่ `/admin` เชื่อมอีเมลและรหัสปฏิทินเดิมซ้ำกับ token ใหม่
3. กดตรวจตัวอย่าง จะแจ้งว่าเป็นการต่ออายุ token เท่านั้น แล้วกดสลับ ระบบเปลี่ยนเฉพาะ token ที่เก็บไว้ **ไม่คัดลอกข้อมูลและไม่หยุดการบันทึกนาน**

## Rollback (ย้อนกลับไปปฏิทินก่อนหน้า)

ย้อนด้วยวิธีเดียวกับการสลับ โดยเชื่อมบัญชีเดิมแล้วสลับกลับ:

1. รันสคริปต์ด้วย `--email` ของบัญชีก่อนหน้า (เช่น `hnbcmu@gmail.com`) และเข้าสู่ระบบด้วยบัญชีนั้นในเบราว์เซอร์
2. ที่ `/admin` กรอกอีเมลนั้น, token ที่ได้ และรหัสปฏิทินของปฏิทินก่อนหน้า (ถ้าเป็นปฏิทินหลักเดิมจาก Vercel ใช้ค่า `GOOGLE_CALENDAR_ID` หรืออีเมลของบัญชีนั้น)
3. ตรวจตัวอย่าง แล้วกดสลับกลับ การคัดลอกทำซ้ำได้ปลอดภัย (ข้าม event ที่มีอยู่แล้ว) และพา event ที่สร้างหลังการสลับครั้งแรกกลับไปด้วย

**คำเตือน:** การลบไฟล์ตั้งค่าออกจากที่เก็บเพื่อให้ระบบกลับไปใช้ปฏิทินหลักจาก Vercel จะทำให้ระบบกลับไปได้เร็ว แต่ **event ที่สร้างหลังการสลับจะไม่ตามกลับไปด้วย** ใช้เฉพาะเมื่อยอมรับการสูญเสียนั้นได้

## ข้อควรระวัง

- ห้ามแก้ในปฏิทินโดยตรง หลังสลับ ให้แก้ผ่านแอปเท่านั้น
- ปฏิทินสำเนาเพิ่มเติม (phase C) ไม่รวมในรุ่นนี้
- ห้ามใส่ token, คีย์ หรือรหัสปฏิทินจริงลงในไฟล์ใด ๆ ในโค้ด
